# Flujo Git

Antes de cambiar archivos, revisa `git status` y el diff para distinguir el trabajo existente del nuevo. No descartes, restaures ni sobrescribas cambios del usuario.

Agrupa cambios por intención y mantén cada commit enfocado. Antes de proponer un commit, resume qué incluye y revisa el diff staged. No hagas commit, push, merge, rebase ni publiques cambios salvo que el usuario lo haya pedido explícitamente.

Al preparar un pull request, explica el problema, el cambio y las verificaciones realizadas. No afirmes que una verificación pasó si no se ejecutó; menciona límites y riesgos observables.
